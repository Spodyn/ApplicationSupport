# Direct Messages

Active users can find Direct Messages in the sidebar on desktop and in the navigation drawer on mobile. Search existing conversations by display name or choose New Message to search active teammates. Enter sends a text message and Shift+Enter inserts a line break. The list shows unread counts. Opening a conversation in a visible tab advances that user's read position.

Each deployment keeps internal text in its own PostgreSQL database. Migration V42 creates dedicated conversation, message and per-user write-budget tables. A unique constraint on the ordered participant pair prevents duplicate conversations. Deactivation preserves historical messages for the active participant. User references prevent an accidental hard delete that would leave messages without authors. DM content does not enter Case, provider-delivery, application audit or realtime event records.

The OpenAPI contract defines authenticated recipient search, conversation list/detail/start, message history/send and read-position update under /api/v1/direct-messages. The recipient directory exposes only account IDs and display names. Cursors are signed and scoped to the requesting account and query. A nonparticipant receives the same 404 as an unknown conversation, including when the caller has the ADMIN role. CSRF applies to every write. The send command takes an Idempotency-Key and uses the standard 24-hour replay window. Only the acknowledgement and request digest enter the replay store. A conversation row lock orders concurrent messages and protects monotonic read-position updates. PostgreSQL enforces 60 new conversations or sends per account per minute. Replays return the prior acknowledgement without consuming write capacity.

The backend publishes a conversation ID to the participants' authenticated /user/queue/direct-messages destinations after commit. STOMP clients cannot supply a target user or send a message frame. The WebSocket transport rechecks the browser session on inbound and outbound messages. The client refreshes authoritative REST data after a hint or reconnect, with periodic refresh on the open workspace as a fallback. Private responses follow the API's no-store and service-worker network rules.

Message bodies are plain text with a 4,000-character limit. The scope is one-to-one text messaging. PostgreSQL stores and orders the authoritative message history. Realtime is a refresh hint and can be missed during transport interruption.
